六年知识地图

把小学六个年级的考点做成一张能点进去的大地图，点到最后是一道题——答完颜色会变。方向是对的，但你现在这个设计里有三处会在做到一半时把它杀死。下面这套方案先修那三处，再谈地图。

覆盖1–6 年级 · 5 学科
体量约 3000 个知识点
原型三年级数学（已可交互）
判分确定性优先，LLM 兜底

这个想法站得住，也站不住

先分开说。下面左边是这个想法里真的对的部分——不要动它；右边是四处如果不改设计就一定会失败的地方，它们不是"难度大"，是"按原设计做出来会是错的"。

站得住的三点

  • 掌握度可视化回灌到图谱——这是整个想法里最有价值的一条。一眼看出哪里弱，比任何分数报表都直观。市面上做 K12 的很少把这件事做对。Khan Academy 的 mastery、Anki 的复习热力图都证明了它有效
  • 年级 → 学科 → 知识点 的三级下钻——符合认知，也让"六年"这个吓人的体量变得可入口。第一级给了六个，而不是三千个。
  • 先修关系本身就是孩子最容易断的地方——三年级除法崩掉，根往往在二年级的乘法没过关。一张画着先修边的图能把这个显示出来，这是"分数"永远做不到的。

会杀死它的四点

  • "收集课本内容"这一句要删掉。教材原文、例题、插图都在著作权保护里，人教/北师大/苏教各家还都不一样。能做的是考纲与知识点体系——那是公开的课标内容。这不是法律顾问式的谨慎，是工作量差五倍的现实问题
  • "让 LLM 判分"在小学数学上会翻车。模型算三位数乘法是真的会错，而且错得很自信。判断对错这件事根本不该交给一个概率模型——选择比对选项、填空规范化匹配、计算用符号求值，都能做到 100% 准确，还免费。LLM 只该干一件事：把开放题的文本映射到"评分点命中"
  • "社区算法生成关联图谱"被当成了它做不到的东西。Louvain / Leiden 是聚类——它按你喂的边分组，不发现教学规律。用它自动命名知识簇有用，指望它算出"该先学什么"不行。边才是本体，聚类只是副产品
  • "答对 → 分数高 → 颜色深"是假的掌握感。孩子把一科刷一遍，整张图全深了。一次答对说明不了任何事。要改成间隔重复：答对只是把下次复测时间往后推
图版 一

原型：点一遍你就懂了

这是真的能点的。六个区域 → 学科 → 知识图谱 → 点一个节点出题 → 作答 → 判分 → 看颜色和复测时间怎么变。原型只做了三年级数学一条链路——这本身就是方案的建议（见下面的工序）。

三处要改的设计，和改法

① 边从哪来 —— 这是图谱质量的唯一决定因素

不要让 LLM"生成关联"。让它做一件窄得多的事：给两个已知知识点，判断它们是三种关系里的哪一种。三种关系都有客观依据，可校对：

先修（学 B 之前必须先会 A）· 并列（同级、互相印证）· 易混（孩子会搞混的一对）。这三种边加起来就是教学论里"知识结构"的全部骨架。

边定好之后再跑聚类——这时候 Louvain 才真的有用：它会自动把"万以内加减、乘一位数、除数一位数"聚成一块，你只需要给它起个名字叫「整数运算」。它是命名器，不是发现器。

② 判分分层 —— 能确定性判的，绝不问 LLM

选择 / 判断：比对，100% 准，零成本。

填空：先规范化再匹配——全角转半角、去空格、统一标点，再用一张多答案表（3/三/3个 都算对）。覆盖绝大多数填空。

计算题：不比对字符串，用符号求值验证表达式等价。1/2 和 0.5 和 二分之一 是同一个数。

只有文本题（说理、作文、阅读理解）才调 LLM，而且它返回的不是分数，是评分点命中情况——"有没有指出单位不同"这种事它能可靠判断，"该给几分"它不能。

③ 掌握度 —— 把"答对次数"换成"记忆稳定性"

用现成的间隔重复算法（FSRS 或 SM-2，都有开源实现）。规则简单：答对只是把下次复测时间往后推，答错就拉回到明天。

颜色深浅由稳定性算出来，不由答对次数算。区别是决定性的——刷一遍不会让图变深，只有隔了很久还记得才会。

顺带白拿一个功能：图上的颜色自动告诉你今天该复习什么。这比"错题本"有用得多。

④ 地图放最后做 —— 它是最不值钱的一环

六个区域的草地、湖面、沙丘，用程序化生成（噪声 + 等高线）两天就能出，而且以后想换皮肤随时换。它是包装。

护城河在图谱质量和判分准确度上。建议 v1 不要地图，直接就是图谱；地图是 v2 套上去的一层。反过来做的话，你会花一个月做出一个漂亮但不能用的东西。

这个原型为了让方案看得见，把地图做了——但那是我替你花的成本，不该是你先花的那笔。

整张图只需要这三种边。每一条都是可以拿去问老师"这对不对"的客观陈述——这就是为什么它可校对，而"让模型生成本体"不可校对。

数据模型

一张图 + 两张表。知识点是唯一的实体，掌握度是独立的一张表——因为它是每个孩子各一份的，而知识点是全站共享的。

实体字段说明
knowledge_pointid · 年级 · 学科 · 名称 · 权重 · 掌握判据全站共享。掌握判据是必须有的一个字段：能做出什么题算会了。没有它就无法测。
kp_edgefrom · to · 类型（先修/并列/易混）有向图。这张表的质量 = 产品的质量。
questionkp_id · 题型 · 题干 · 选项 · 答案 · 规范化规则 · 评分点一道题属于一个知识点。生成一次入库，不每次现生成——省钱，而且同一个孩子两次看到同一题答案不会变。
mastery用户 · kp_id · 稳定性 · 难度 · 到期日 · 最近一次结果每个孩子一份。颜色、复习队列、薄弱清单全从这张表算。

一个容易被忽略的字段：权重。知识点不是同等重要的。"两位数乘两位数"在三年级下学期的分量远大于"吨的认识"。权重应该是该知识点在真题里出现的频率，而不是拍脑袋定的。它决定两件事：图上节点多大，以及薄弱时该先补哪个。

工期与代价

诚实的数字。真正贵的是校对，不是模型调用——模型那部分便宜到可以忽略。

阶段范围工作量产出
0 · 打通三年级 · 数学1–2 周全链路可跑：16 个知识点、约 150 道题、判分、掌握度、图谱。就是这个原型的完成版
1 · 一个学科做全1–6 年级 · 数学3–4 周验证"跨年级的先修边"真的有用——这是整个产品最独特的价值，也最该早验证
2 · 铺开6 年级 · 5 学科2–3 个月约 24 个"学科×年级"单元，约 3000 知识点、3 万道题
3 · 包装大地图 + 皮肤1–2 周六个区域的游戏化外观

成本构成说清楚：知识点体系是 LLM 抽取 + 人工校对，每个"学科×年级"单元约 1.5 人日——贵的是那 1.5 人日，不是模型。出题是 LLM 批量生成一次入库，3 万道题的总 token 成本按现在的便宜模型算不到一百块，再抽检 5%。所以这个项目的成本几乎全是人时，而人时集中在最前面的校对环节。

红线：这三件事不确认清楚就不要写代码

下面每一条都是"做到一半才发现"会让人想推倒重来的类型。我的建议顺序是：先把这些问清楚，再决定做给自己孩子用还是做成产品——这两个答案的工程取舍完全不同。

教材版权content

《义务教育课程标准（2022 年版）》是公开的，课程内容与学段目标可以引用；教材正文、例题、插图不能。人教版、北师大版、苏教版、外研版各成体系，各地考纲也不同。第一版必须砍到只做一个版本（建议人教版，覆盖面最大），否则工作量直接乘五。落库的应该是"知识点 + 先修关系"，不是课文。

教育应用备案compliance

面向中小学生的教育类 App 在国内有专门的备案要求（教育移动互联网应用程序备案）。如果只给自己孩子用、跑在本地，这条不适用；一旦上架或对外提供服务就适用。具体条款和执行口径请找懂行的人核实——我只负责提醒你现在就该问，而不是做完再问。

未成年人信息privacy

《未成年人网络保护条例》2024 年 1 月 1 日施行，处理不满十四周岁未成年人的个人信息需要监护人同意。第一版最省事的规避方式是根本不做账号体系——掌握度数据存在本机，不联网、不上传。这既绕开了合规，也让你自己孩子用起来更放心。等链路验证完再谈账号。

工序

顺序是有信息的，不要打乱。前四步做完之前不要开始第五步。

  1. STEP 1

    定口径先做这个

    确定版本（人教版？）、确定"掌握判据"怎么写、确定权重从哪来（真题频率）。这一步产出的是纸面规则，不是代码。跳过这一步会直接导致知识点表做两遍。

  2. STEP 2

    建三年级的数学知识点表

    约 16–20 个知识点，每个带权重和掌握判据；再标三种边。这张表手工过一遍——它是整个产品的地基，也是唯一值得你亲自看一遍的东西。规模小到可以在一张纸上画完。

  3. STEP 3

    判分引擎 + 掌握度引擎

    两个纯函数模块，不碰界面。确定性判分那套（规范化、多答案表、符号求值）和 FSRS。这两块是整个系统里唯一需要写对的代码，其余都是展示。

  4. STEP 4

    出题并入库，把链路跑通

    给每个知识点生成 8–12 道题，覆盖四种题型，跑一遍完整流程：做题 → 判分 → 掌握度变化 → 复测队列。到这里核心产品已经完成了，剩下都是包装。

  5. STEP 5

    跨年级验证

    把 1–6 年级数学都做出来，然后看一件事：三年级的除法薄弱，图上能不能连回二年级的乘法。能，这个产品就成立了；不能，说明边的质量还不够，回去修边。最该早验的一步

  6. STEP 6

    铺学科，最后套地图

    语文的开放题最难判分，英语和科学相对好做，建议顺序是数学 → 英语 → 科学 → 语文。六个区域的皮肤放在最后——它随时能加，而且加早了只会让人误以为产品已经做完了。

需要你定的三件事

这三个答案会改变方案，我不替你猜。

给谁用

只给自己孩子用 → 单机、无账号、无备案，两三周就能用上。

想做给别的孩子用 → 先解决备案和版权，工程取舍完全不同，周期是月不是周。

先做哪个学科

我的建议是数学：答案客观、判分能做到 100% 准、先修关系最清晰，是全链路最好的试验田。

如果目标是"孩子明天就能用上"，那取决于他现在最弱的是哪科——这比技术判断更重要。

教材版本

人教 / 北师大 / 苏教 / 外研……只能选一个开始。

选错版本的代价不是返工，是知识点表对不上孩子课本，孩子第一眼就不认——那是最伤使用意愿的。

要不要我现在动手

你说一声，我按工序从 STEP 2 开始：先把三年级数学那张知识点表列出来给你过目。那张表不用写代码，是可以直接讨论的。

表定下来之后，判分和掌握度两个引擎我一个人就能写完。
