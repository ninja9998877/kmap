# 六年知识地图（kmap）

小学 1–6 年级 · 三科。**年级 → 学科 → 知识点** 三级下钻，点到最后是一道题。

题目**现场出**（不做题库），答案由我们自己重算验证，掌握度按"隔了多久还记得"着色。

## ★ 代码公开，资料私有

这个仓库里**只有工具**：判分、出题、界面、这个文件。
**资料在另一个私有仓库**（`kmap-data`）：教材目录、知识点图谱、掌握度。

两样东西的性质完全不同 —— 工具谁都可以看，资料是这个家自己的。

```
某个目录\
├── kmap\          这个仓库（公开）—— 代码
└── kmap-data\     资料（私有）    —— 图谱 / 目录 / 掌握度
```

怎么找到资料由 `paths.py` **一处**决定，顺序是：
`$KMAP_DATA` → 代码旁边的 `../kmap-data` → 代码目录本身。
所以两个目录并排放着就什么都不用配。**服务启动时会把实际用的目录打印出来** ——
免得出现"明明有文件却说没有"那种查半天的情况。

安卓外壳的 APK 也不在这里：外壳本身在 `kmap-shell`（另一个公开仓库），
签名用的 keystore 在第三个地方（不提交）。

## 跑起来

```bash
cd kmap
python serve.py
```

打开 <http://localhost:8890>。同一局域网里的手机 / 平板也能开 —— 见下一节。

## 孩子在平板上怎么打开

**服务开着就行**，平板不用装任何东西。启动时终端里会打印两样东西：

```
  手机 / 平板  http://10.0.0.24:8890

  ↓ 平板/手机扫这个（不用手打地址）
  █▀▀▀▀▀▀▀█▀███▀███▀█▀▀▀▀▀▀▀█
  █ █▀▀▀█ █▀▀█ █▀▀█▀█ █▀▀▀█ █
  …
```

**平板扫那个二维码**（微信/相机/浏览器都行），比让孩子手打 IP 靠谱 ——
`10.0.0.24:8890` 这种十几个字符，孩子在平板上敲一遍大概率敲错，
然后你得到的反馈是"打不开"，而不是"我敲错了"。

三个前提，缺一个就是"打不开"：

1. **平板和电脑连同一个 WiFi。** 不同网段的话服务器会返回 403，
   而且页面会**明说**是哪台设备被挡了、允许的网段是什么 —— 不再是干巴巴一句
   `forbidden`。
2. **服务得一直开着。** 关掉终端窗口 / 电脑睡眠，平板就断了。
   （Windows 睡眠尤其容易中招：电脑看着还在，网却断了。）
3. **防火墙放行。** 见下面那条命令。

### ★ 地址会变，每次都要重新扫

这台电脑的**MAC 是随机的**（Windows 的"随机硬件地址"），所以路由器给的
IP 会变 —— 写这份文档时是 `10.0.0.24`，上个星期还是 `10.0.0.205`。
**所以别把二维码截图存下来反复用**，每次启动都以终端里新打的那一个为准。

嫌烦的话有两条路：

- **在路由器里给这台电脑做 DHCP 保留**（按 MAC 绑一个固定 IP）—— 一劳永逸。
  但前提是先把"随机硬件地址"关掉，否则 MAC 每次都在变，绑不住。
- 就每次扫一下终端里的二维码。**顺手，不折腾。**

### 防火墙

现在**能用，但是碰巧**：系统里有一条允许 `python.exe` 入站的规则（公用配置
文件），而 WiFi 恰好被 Windows 归为"公用网络"，所以放行了。
两个隐患：

- 那条规则**认的是 python.exe 的完整路径**。哪天 Python 升到 3.13、
  或者改用虚拟环境跑，路径变了，规则就不匹配了 —— 症状是**突然打不开，
  而什么都没改**。
- 它放行的是**任意端口、任意来源**，比需要的宽。

稳妥的做法是加一条只管 8890、只管局域网的小规则（**要用管理员权限的终端**）：

```powershell
netsh advfirewall firewall add rule name="kmap 8890 (LAN only)" `
  dir=in action=allow protocol=TCP localport=8890 remoteip=10.0.0.0/24
```

> **什么时候需要改那个网段**：不写死。服务的白名单默认是**自己算出来的**
> —— 取本机实际所在的网段（会自动跳过 Tailscale 的 `100.x` 和 `169.254.x`），
> 所以换路由器也不用改代码。真要手动指定就用环境变量：
> `KMAP_ALLOWED=192.168.1.0/24 python serve.py`。

出题要调模型，配置放在 `kmap/.env`（`.gitignore` 已挡住，别提交）：

```
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-v4-flash
LLM_API_KEY=sk-...
```

没配也能打开页面，只是点「开始」会报错。

## 目录结构：一个格子一个文件

**1–6 年级 × 3 学科 = 18 个格子**，每格对应一个文件（在 `kmap-data/` 里）：

```
graph-{年级}-{学科}.yaml        例：graph-6-math.yaml
学科名：math / chinese / english
```

**加内容 = 放一个文件，代码一行都不用动。** 服务启动时扫数据目录，没文件的格子
在界面上照常显示，只是标着「即将支持」—— 地图是完整的，也看得出东西在长。

现在 **16 / 18 个格子有内容**（375 节点 / 339 边），缺的是五、六年级语文
（没找到可靠的目录源）。逐格清单在 kmap-data 的 README 里。

## 文件

| 文件 | 做什么 |
|---|---|
| `serve.py` | 局域网服务 + API。白名单按**本机实际网段**自动推导，可用 `KMAP_ALLOWED` 覆盖 |
| `learn.html` | 全部界面（三级下钻 / 答题 / 结算），卡通风格 |
| `paths.py` | **唯一一处**决定"资料在哪"的地方。代码公开、资料私有，见上 |
| `grader.py` | **判分引擎**。纯函数，全程 `Fraction`，不用浮点 |
| `mastery.py` | **掌握度**。SM-2 + 把答题速度折成四档 |
| `tutor.py` | **出题器**。调模型出题，然后自己重算校验答案 |
| `index.html` | 最初那份产品方案与原型（页面上 `/plan` 看） |

还有三个脚本 —— `fetch_catalog.py` / `build_graph.py` / `check_graphs.py`。
它们是**造资料的工具**，住在**这里**（工具公开），但读写的全是 `kmap-data/` 里的
东西（走 `paths.py`，不写死路径）。

分界线就是这么划的：**能造出资料的机器是工具，资料本身不是。**

## 数据是怎么来的（以及为什么这么记）

**取数纪律**：数据来源必须和可信度一起记。

```
fetch_catalog.py   抓教材目录（网络检索）
      ↓
catalog/*.json     原始素材，带 _source 块（网址、抓取日期、可信度、警告）
      ↓
build_graph.py     让模型把目录「展开」成知识点（掌握判据 / 权重 / 边）
      ↓
graph-{年级}-{学科}.yaml
      ↓
check_graphs.py    批量校验（悬空边 / id 重复 / 判据不可测 / **单元不在目录里**）
```

每个节点都带 `source` 字段，只有三档：

| 值 | 含义 |
|---|---|
| `textbook` | 来自教材目录，可信 |
| `curriculum` | 来自课标，可信 |
| `inferred` | **模型推的，必须核** |

现状：**单元结构标 textbook（检索来的），掌握判据/权重/边标 inferred（模型长的）**。
这份图谱的骨架是检索来的、肉是模型长的 —— 两者在文件里分开标着，不许混。

### 覆盖情况（2026-09-25）

**16 / 18 个格子**，共 375 个知识点 / 339 条边：

| 年级 | 数学 | 语文 | 英语 |
|---|---|---|---|
| 1–4 | ✓ | ✓ | ✓ |
| 5 | ✓ | — | ✓ |
| 6 | ✓ | — | ✓ |

**还缺**：五、六年级语文（没找到可靠的目录源）。缺的格子在界面上显示「即将支持」。

### ★ 两条踩过的坑，都写进校验了

1. **模型会凭空补目录里缺的行。** 教材目录里六上第四单元那一行排版缺失，
   模型就自己补了一个「比和按比例分配」出来。`check_graphs.py` 现在拿目录当
   白名单硬对一遍节点的 `unit`。
2. **目录版本不等于孩子的课本。** 抓来的是 2013 版（教辅站收录），而 2026 秋
   全国已完成新教材替换。**每份 yaml 的 `known_gaps` 里都写着这句话。**

## 平板适配（孩子用的是安卓平板）

**平板最常用横屏**，而这一直没测过 —— 现在 `kmap-tablet.mjs` 会跑
1280×800（横）和 800×1280（竖）两个真实视口，查：

- 首页大地图：六块地形有没有重叠、够不够大、**一屏能不能看完**
- 答题页：题干字号、选项和按钮的触摸目标

针对安卓浏览器另外处理了几件在桌面 Chrome 上看不出来的事：

| 事项 | 处理 |
|---|---|
| 点按钮时的蓝色方块 | `-webkit-tap-highlight-color:transparent` |
| 长按选中按钮文字 / 弹菜单 | 可点元素 `user-select:none` + `touch-callout:none`（**题干保持可选**，孩子可能想复制去问人） |
| 横屏时字体被系统放大 | `-webkit-text-size-adjust:100%` |
| 10 寸屏上字偏小 | ≥1000px 时正文 18px、题干 22px |
| **四边安全区** | 原来只让开了左右（横屏时刘海在侧面），上下没管 —— 底部被手势条压、顶部被状态栏盖。现在四边都用 `env(safe-area-inset-*)`；没有安全区的设备上 `env()` 返回 0，等于没写 |
| **输入法弹起遮住输入框** | 安卓上软键盘会把页面顶上去。聚焦后等键盘动画走完（320ms）再把输入框滚到视野中间 |

还有一处**布局**问题：图谱是**单元级**的（多数单元只有 1 个知识点），
原来单元块竖着一列排到底 —— 横屏平板上每行就一张 240px 的卡，右边一大片空白
（症状是**五个视口页高完全一样**，都是 1597）。现在单元块按宽度并排：

```
≥760px  2 列      ≥1180px  3 列
```

实测页高：横屏 855 / 竖屏 1280 / 小平板 1591 —— 确实跟着宽度变了。

## 包装：地图 → 城堡 → 领主 → 军团 → 将领 → 敌军

```
年级   → 地图（地形）+ 一座城堡        ← 显示在年级选择界面（首页）
城堡   → 三个学科 = 三个领主
领主   → 他的军团
将领   → 知识点
敌军   → 题目
把将领的部队打光 = 完全掌握那个知识点
```

**这层包装不需要任何新数据**，是套在「年级 × 学科 × 知识点 + 掌握度」上的。
判分、SM-2、先修边、效率块全都原样不动。

### ★「消灭」用的就是现有那条线，没有第二个判据

`mastery.strength()` 的公式是 `min(1, log1p(间隔) / log1p(21))` ——
**间隔 ≥ 21 天时它精确等于 1.0**。所以"军团被消灭"和"图上颜色最深"是
**同一件事**，不会出现"你刚说他会了、图又说不会"。

而 SM-2 的间隔台阶是 `1 → 6 → 15 → 38 → 95`，分档正好落在台阶之间：

| 状态 | 判据 | 人话 |
|---|---|---|
| `untouched` | 没测过 / 间隔 0 | 未遭遇 |
| `engaged` | 间隔 1–5 | 遭遇中 |
| `suppressing` | 间隔 6–20 | 压制中 |
| `destroyed` | 间隔 ≥ 21 | **已消灭** |
| `unstable` | **曾经到过 21**、现在掉下来了 | 有异动 |

取到 21 天大约要 4 次成功复习、跨越三周多。所以**短期看得到进展**
（遭遇中→压制中，进度条一直在动），但**"消灭"要真的记住才算，刷一遍刷不出来**。

### 为什么有「有异动」这一档

答错时 SM-2 把间隔打回 1。光看当前值分不出"从没学会过"和"学会过又忘了"，
而这两件事对孩子**完全不一样**：前者要教，后者只要去守一下。

所以 card 上多记了一个 `best`（历史最大间隔，`update()` 里维护）。
没有它就只能二选一：要么把战果一抹了之（孩子觉得"我明明打下来的"），
要么继续显示"已消灭"（**地图说谎**，而这是本项目最忌讳的错）。
有异动是第三条路：保留战果，同时明说"阵地在松动，去守一下"。

### 状态只有一处实现

`mastery.state()` 是唯一判分档的地方 —— 前端卡片和军团统计都读它。
前端再拿 `strength` 判一遍的话，两处不一致时**不会报错**，
只会出现"领主说消灭了 3 个、点进去只有 2 个"这种要查半天的事。

自测里有一条**守门员**盯着这件事：`strength(21) == 1.0` 和 `state == destroyed`
必须是同一条线。用变异测试验过（改成 20 天封顶、或把 21 改成 15，都会红）。

### 界面

- **首页**：每块地形上一座纯 SVG 画的城堡（跟地形一样零素材）。旗色就是战况，
  下面写着「已消灭 X / Y 员将领」——比原来的"三科 107 个"具体得多，
  而且**有限**（能打完），这是这套叙事真正起作用的地方。
- **城堡页**：三个领主各一张卡，带**堆叠**战况条
  （已消灭 / 有异动 / 压制中 / 遭遇中 / 未遭遇）。
  用堆叠而不是单一百分比，是因为单一百分比会出现"条快满了但只消灭 3 个" ——
  那等于说谎。
- **军团页**：将领卡加状态徽章 + 图例 + 三个术语问号。
- **结算页**：一行战报（这位将领打成什么样、军团还剩几员）。

### ★ 四处刻意**不改**

| 不改 | 为什么 |
|---|---|
| **单元名**（`上册 一、分数乘法`） | 那是**课本里的单元**。改成军事编号就切断了孩子拿书对照的能力 —— 包装不能吃掉实用性。 |
| **权重** | 它是"考试里出现的次数"，是个真概念（已有术语问号解释）。改名成"兵力"就把它变成比喻了，而孩子需要的是前者的字面意思。 |
| **题干 / 答案 / 讲解 / 掌握判据** | 项目的硬规矩：严谨内容一个字不改，只有"壳"能随便。 |
| **结算页的「省下来的力气」** | 那是全部激励设计的落点。战争叙事是加在它上面的，不是替换它。 |

## 驱动力：卖的是「省力气」，不是「更努力」

这条是从一个观察来的：**孩子对"全班第一"未必有兴趣，但对"我用更少的力气
拿到了同样的结果"很有兴趣。** 那是**杠杆感**，不是攀比。

而且它比"努力"健康得多 —— 努力是无底洞（总有人更努力，孩子迟早认输），
效率是可以一直赢的。

这个产品**天生就是效率工具**，只是以前没讲出来：

| 机制 | 它的效率含义 |
|---|---|
| 间隔重复（FSRS） | 只在**快忘时**才让你复习。没到期就不碰 —— 没到期还练是白费 |
| 根因诊断（先修边） | 一个点崩了，根可能在**三年前那个乘法**。补那一个，胜过刷一百道 |
| 现场出题 | 不给你一千道题游 —— **只出你现在需要的那几道** |

所以结算页有个「**省下来的力气**」块，说的三件事：

```
「圆」以前是你的坎 —— 你在这儿栽过 3 次。今天一次过。
上一次做这一节花了 5 分 10 秒，这次 3 分 20 秒。
这张图还有 7 个点今天不用碰 —— 都没到期，现在做是白费。
```

★ **这几行里的每个数字都是真的**（后端从进度文件里算），
没有一个"一般人要练 4 次"那种编的。**编的数字孩子迟早识破，
而那时候连真的那部分他也不会信了。**

也**没有做**：连续打卡天数（断一天就崩，然后整个系统对他失效）、
排行榜（家里一个孩子，跟谁比？）、限时（和"数学要想的时间"冲突）、
抽卡（那是赌博机制）。

## 草稿纸

做题时孩子可以在平板上**直接用手（或触控笔）画**。纯本地，画的东西
**不发给服务端** —— 草稿是思考过程，不是作答内容，没有理由离开这台设备。

**为什么是并排，不是盖住题目的浮层**：算到一半要回头看题目，圆、圆柱、
扇形统计图这些尤其。浮层一盖住就得反复开合，而开合会打断思路。
所以宽屏（横屏平板）上草稿纸在题目右侧，窄屏改成上下排；窄屏默认关着。

几个**不写就会坏**的地方，都写在 `learn.html` 里了：

| 事项 | 不做的后果 |
|---|---|
| CSS 里 `touch-action:none` | 手指一画页面就跟着滚，线是断的。**桌面浏览器测不出来**（鼠标不滚页面） |
| 画布按 `devicePixelRatio` 放大 | 高分屏上线是一团糊的 |
| 只认一个 `pointerId` | 孩子握平板时**手心压在屏幕上**，会从手心窜出一条直线 |
| 笔画存下来、尺寸变了重画一遍 | 转屏 / 改窗口大小，画的东西就没了 |
| 实时画和重画**共用同一个** `padPath()` | 两处各写一遍 → "画的时候是弯的、重画之后变直了"，不报错、只是不对 |

自测：`node kmap-scratch.mjs`（`.selftest/` 里）。它验并排布局、dpr 放大、
画得出来、撤销/清空、**交卷后草稿还在**（孩子要对着自己的草稿看讲解）、
作答入口没被碰坏，以及拿真触摸事件走一遍。

其中"画的时候页面不滚"这条**第一版是空转的** —— 1280×800 上那个页面根本滚不动，
没有东西可滚，"没滚"当然成立，连 `touch-action` 拿掉都测不出来。
现在先塞一个高占位元素让页面真能滚，**并先断言这个前提成立**，再验不滚。

## 术语问号

项目里那些词（**权重**、**掌握度**、**该复习**、**先修**、**连对**）旁边有个小问号，
点开是给孩子看的解释 —— **不是定义，是"这个词对我有什么用"**：

> **权重是什么？**
> 这个词在考试里出现的次数。5 分的差不多每次都考，1 分的偶尔露个脸。
> 所以分高的先弄会 —— 花一样的力气，回报差好几倍。

词条集中在 `learn.html` 的 `GLOSSARY`，想改措辞只改那一处。

两个实现细节：
- 问号视觉上只有 19px（不抢戏），但用 `::after` 把**热区撑到 ~45px**（手指点得准）。
- 问号用**事件委托**挂。卡片是每次渲染动态生成的，逐个绑迟早漏一个 ——
  （这个项目已经栽过"后插入的 DOM 事件没绑上"）
- 知识点卡片为此从 `<button>` 改成了 `<div role="button">`：
  **HTML 不允许 button 嵌 button**，浏览器会自作主张闭合外层、结构就乱了。
  代价是键盘可达性要自己接（Enter / Space）。

## 语气：壳可以随便，内容必须准

**分界线**：

- **严谨内容**（一个字不改）：题干、答案、课文、讲解（`why` / `teach`）、
  教学建议、先修提示、掌握判据。这些由服务端生成，**不为了活泼牺牲准确**。
- **壳**（可以随便）：按钮、反馈词、加载提示、状态文案、鼓励语。

基调是**六年级（12 岁）：简短、平视、有点游戏感**。

- ✗ 不用"你真棒""真聪明"—— 捧的是天赋不是努力，而且肉麻
- ✗ 不堆网络梗 —— 过时快，家长看着也别扭
- ✓ 说清**具体哪一步对了 / 差在哪**

实测模型的鼓励语（答错一道圆面积题）：

> 你公式记牢了，就是 6 是直径不是半径——先除以 2 再平方，这一步补上就对了。

前端那些固定文案集中在 `learn.html` 的 `TONE` 对象里，想调只改那一处。

## ★ 答错之后怎么办，三科不一样

这是本科目最重要的一条产品决定。**用同一套糊三科是错的** —— 因为三科"答错"
的原因根本不同：

| | 答错多半是因为 | 所以给 |
|---|---|---|
| **数学** | 某一步不熟（程序性知识） | **更小的一步**（梯子）—— 拆小了就能过去 |
| **语文** | 没读到 / 不知道 | **讲透考点 + 补背景 + 同类例子** —— 让他留下印象 |
| **英语** | 没记住 | **联想记忆 + 使用场景 + 易混对照** —— 挂到已知的东西上 |

实测输出（语文《观潮》答错）：

```
这道题考的是：课文的写作顺序——作者是按观潮的时间先后写的。
多知道一点：钱塘江大潮自古被称为"天下奇观"，农历八月十八前后最壮观…
再举个例子：写一场雨，也可以按"雨前—雨中—雨后"的顺序写。
```

英语答错 Teachers' Day：

```
怎么记：开学第一天是 9 月 1 日，Teachers' Day 就在开学后第十天 → 9 月 = September
什么时候用：开学第一周，同学问你 When is Teachers' Day?…
别混了：October（十月）—— 国庆节是 October 1st，两个 -ber 结尾的月份最容易混…
```

这三段由出题器按学科产出（`tutor.SUBJECT_RULE[subject]['recover']`），
前端按字段渲染。**一个学科只会拿到它该用的那一个**。

## 三条不能动的地方

这三条是这套东西和"让模型出题、让模型判分"的区别所在：

1. **答案由我们自己验。** 模型出完题，`tutor.validate()` 拿它给的算式用
   `grader.eval_expr` **重算一遍**，比对不上就丢弃重出。孩子看到的每道题，
   答案都是独立验过的。
2. **答案不发给前端。** 题出好后存在服务端内存里，前端只拿题干和选项，
   判分在服务端做。否则按一下 F12 就看见答案了。
3. **颜色由「隔了多久还记得」算，不由答对次数算。** 刷一遍不会让图变深
   （`mastery.strength` 只看间隔）。

另外几条产品决定：**不给孩子看计时器**（计时在后台，只用正向反馈）；
**答错之后按学科给不同的东西**（见上一节）；
**没过一半就指回先修节点**（"根在更前面"——这是图谱里那些边唯一真正派上用场的地方）。

### ★ 自测**必须**用一份临时进度

```bash
cd kmap
KMAP_PROGRESS=/tmp/kmap-test.json python serve.py
```

不这么干的话，**测试数据会写进孩子的真实进度**。2026-09-26 就出过这事：
`m6a-yuan` 攒了 8 次、`m6-yuan-mianji` 6 次"作答"，每题耗时 **0.043 秒**
——脚本点出来的。界面上**看不出哪条是假的**，那张图会一直脏下去。

现在会作答的脚本（`kmap-flow` / `kmap-queue` / `kmap-prereq` / `kmap-feedback`）
**开跑前先问服务用的是哪份进度文件**（`/api/health`），是真实那份就**直接退出**：

```
✗ 停一下：这个服务连的是**孩子的真实进度**（progress.json），不是自测用的临时文件。
  …
  正确跑法：KMAP_PROGRESS=/tmp/kmap-test.json python serve.py
```

真要往真实进度里写（比如你自己手动复现一遍）：`KMAP_ALLOW_DIRTY=1 node kmap-flow.mjs`。
实现在 `.selftest/kmap-guard.mjs`。

顺带：端口也能改了（`KMAP_PORT=8891`），这样临时实例能和真实服务**同时开着**，
不用反复起停。

## 安卓外壳（APK）

孩子的设备是**安卓平板**。外壳在 `kmap-shell`（另一个公开仓库）：
一个全屏、**强制横屏**的 WebView，指向电脑上的 `serve.py`。装一次就行。

**★ 装一次就够了** —— APK 里没有 kmap 的任何界面代码，它只是把
`http://<电脑>:8890` 显示出来。所以改 `learn.html`、改图谱、改判分逻辑，
平板上**刷新一下就是新的**，不用重新打包。只有外壳自己变了（图标、横屏、
WebView 配置）才需要重新出包。

出包只能走 CI（开发机没有 Android SDK），**手动触发**。拿到 APK 之后：

```bash
# 放到这里，平板浏览器打开 http://<电脑>:8890/app.apk 就能直接装
kmap/apk/kmap-shell.apk
```

这条路绕开了"微信不能直接发 .apk"的麻烦，也不过云 —— 发的是局域网里的东西。

平板上要允许「安装未知来源的应用」。第一次打开它会自己找服务；找不到会显示
一块**说清楚原因**的面板（不是白屏），并每 3 秒自动重试。
**连按两次返回键**打开诊断面板（给大人看的），上面有构建号。
